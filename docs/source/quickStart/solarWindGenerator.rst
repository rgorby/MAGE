
** cda2wind.py**

Overview
========

cda2wind.py is an attempt at making a do everything event-based solar
wind (bcwind.h5) generator for Gamera. A couple of capabilities exist
for cda2wind, namely the ability to automagically grab OMNI data, or
read from text files generated by omniweb. Some standard options are:

``-t0`` required start time input

``-t1`` required end time input

``-interp`` shade interpolated data points in the resulting png

``-bx`` include Bx fitting coefficients in the output. Enables Bx in
simulation.

``-bs`` disables OMNI's Bowshock location in the output. Defaults to
0,0,0 in Gamera.

``-obs`` selection of the different potential algorithms below

``-f107`` if you want a specified constant f107 in bcwind file. May be
useful for runs without OMNI data.

``-kp`` if you want a specified constant kp. May be useful for runs
without OMNI data.

OMNI
====

Example command:

.. code-block::

   cda2wind.py -t0 2005-08-23T12:00:00 -t1 2005-08-25T12:00:00 -interp -bx


This is the default ``-obs`` option. Grabs OMNI 1 minute resolution
data from cdaweb automagically between the time interval t0 and t1. It
also grabs everything else that's needed like kp, ae, f10.7 etc.

OMNIW
=====

This algorithm combines the final OMNI with OMNI-propagated WIND (or
DSCOVR, ACE) data. The propagated individual spacecraft data is not as
restrictive as the final OMNI. This checks that there are 5 consecutive
points of bad OMNI data and replace with WIND if good.

Example command:

.. code-block::

   cda2wind.py -t0 2013-03-16T00:00:00 -t1 2013-03-20T00:00:00 -interp -bx -fn wind_propagated_march2013_16-19.lst -obs OMNIW


This requires an OMNI-propagated file as input. OMNI-propagated files
can be obtained from omniweb. Right now, this file reader is kind of
dumb. It ignores the fmt file that OMNI generates and only reads the lst
file in a specific order. Also note that t0 and t1 should be equal to
what's in the file. I never figured out a good priority to specify time,
so I just made dumb working code. Here is the order and specific
parameters that is required in the lst file:

.. code-block::

       ITEMS                      FORMAT

    1 Year                          I4
    2 Day                           I4
    3 Hour                          I3
    4 Minute                        I3
    5 BX, nT (GSE)                  F8.2
    6 BY, nT (GSE)                  F8.2
    7 BZ, nT (GSE)                  F8.2
    8 Vx Velocity, km/s, GSE        F8.1
    9 Vy Velocity, km/s, GSE        F8.1
   10 Vz Velocity, km/s, GSE        F8.1
   11 Proton Density, n/cc          F7.2
   12 Temperature, K                F9.0
   13 X(target), GSE, Re            F8.2
   14 Y(target), GSE, Re            F8.2
   15 Z(target), GSE, Re            F8.2

The above list and order can be obtained at:
https://omniweb.gsfc.nasa.gov/form/sc_merge_min1.html Any spacecraft
can be selected but only one can be used at a time. Select the Create
file option and save the lst file. Then point ``-fn`` to the lst.

DSCOVRNC
========

Reads DSCOVR netcdf files obtained directly from NOAA. Find NOAA DSCOVR
data here for the date range you want:
https://www.ngdc.noaa.gov/dscovr/portal/index.html#/download/1643846400000;1644105599999/f1m;m1m;pop
Use the wget command up top to super quickly download all the files. Run
``gzip -d *.gz`` to unzip in place and delete gz files. The cda2wind
will automagically search these files, assuming your date range is
appropriate for all of the DSCOVR files in your directory.  **Currently, does not check the quality flag for DSCOVR.**

Next go to http://wdc.kugi.kyoto-u.ac.jp/dstae/index.html and download
the entire month for event of interest. Select the Dst Output and
IAGA2002-like format options. It will most likely just give you the data
in your browser. copy and paste into a file that you name "dst.dat".
cda2wind is dumb at this part and will always search for dst.dat. No
need to remove the header, cda2wind will search for first time a number
starts the left most column.

Example command after you have the above files in your directory:

.. code-block::

   cda2wind.py -obs DSCOVRNC -t0 2022-02-03T00:00:00 -t1 2022-02-05T00:00:00 -interp


Applies constant time shift to data based on average Vx and average
spacecraft x_gse. Uses very simple propagation to x = 0. At the moment,
it is NOT checking quality flags. There are flags 0 (good), 1
(suspicious), and 2 (bad). I have yet to implement a method to handle a
flag of 1.
